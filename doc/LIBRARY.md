# Meteor libraries (`lib/`)

> Generated by `python3 tools/gen-libdoc.py` from the `///` comments in `lib/*.meteor` - do not edit by hand.

How to use a library: build the modules once with `./build-modules`, then import what you need:

```js
import "../lib/text.obj";
```

Everything that a module imports is available too (`tui` brings `text`, `colors`, `math`, `sys`). All names live in one global namespace, therefore every name in a library starts with the name of its module (`str_len`, `gfx_w`, `kbd_down`, ...) - do not use such names for your own variables and functions.

## sys

*Frame pacing, timers, devices, video mode*

Machine level helpers: frame pacing, timers, device presence.

**Functions**

- `sys_vsync()` - yield until the next host frame (one frame = one pass of the main loop)
- `sys_idle()` - keep the window alive forever (the classic end of a demo)
- `sys_wait_frames(n: u32)` - waits n frames
- `sys_delay_us(us: u32)` - busy wait in microseconds (the VM's own timer, no frame yield)
- `sys_ticks(): u32` - The number of frames since the VM started: it grows by one with every vsync (60 per second at 60 fps, but the frame rate can be changed, so this is NOT a time - use sys_millis() for that).
- `sys_time(): u64` - the wall clock in milliseconds since 1970-01-01 (64 bits)
- `sys_millis(): u32` - Milliseconds from the wall clock, as a u32 that wraps around every 49.7 days: subtract two of them to measure a time (t = sys_millis() - start works across the wrap, too). It goes at the real speed, whatever the frame rate.
- `sys_ram_size(): u32` - size of the RAM in bytes
- `sys_dev_ready(dev: u32): u32` - 1 when the device (std.BUS_DEV_*) is attached and ready
- `sys_beep()` - the VM bell (a short system beep)
- `sys_clear_all()` - wipe both the pixel framebuffer and the text terminal
- `sys_video(mode: u32)` - switch the video mode: 1 = 640x480 (80x30 characters), 2 = 1024x768 (128x48), 3 = 1280x960 (160x60). The mode has to be a constant in the video statement, hence the switch. After a change call gfx_init() / text_init() so the libraries learn the new screen size (gfx_set_mode / text_set_mode do both steps).
- `sys_reboot()` - cold restart of the VM (the program starts again from the beginning)

## math

*Integer maths, fixed point trigonometry, int <-> float*

Integer (and a little f32) maths. The VM has no int <-> float conversion, so trigonometry is done in fixed point: angles are 0..255 (256 = one full turn), results are scaled by 256.

**Functions**

- `math_abs(v: i32): i32` - absolute value
- `math_sign(v: i32): i32` - -1, 0 or 1
- `math_min(a: i32, b: i32): i32` - the smaller of two i32 values
- `math_max(a: i32, b: i32): i32` - the larger of two i32 values
- `math_clamp(v: i32, lo: i32, hi: i32): i32` - v limited to the range lo .. hi
- `math_umin(a: u32, b: u32): u32` - the smaller of two u32 values
- `math_umax(a: u32, b: u32): u32` - the larger of two u32 values
- `math_wrap(v: i32, n: i32): i32` - positive modulo: math_wrap(-1, 10) = 9 (handy for torus worlds and ring buffers)
- `math_map(v: i32, in_lo: i32, in_hi: i32, out_lo: i32, out_hi: i32): i32` - linear remap of v from [in_lo, in_hi] to [out_lo, out_hi]
- `math_gcd(a: i32, b: i32): i32` - greatest common divisor (Euclid)
- `math_lcm(a: i32, b: i32): i32` - least common multiple (0 when one of the numbers is 0)
- `math_pow(base: i32, exp: u32): i32` - integer power, base ^ exp (wraps on overflow)
- `math_isqrt(n: u32): u32` - floor(sqrt(n))
- `math_hypot(dx: i32, dy: i32): u32` - distance of (dx, dy) from the origin, rounded down
- `math_sin(a: i32): i32` - sin of an angle in 1/256 turns, scaled by 256: math_sin(64) = 256, math_sin(192) = -256
- `math_cos(a: i32): i32` - cosine, the same units as math_sin: math_cos(0) = 256
- `math_rand_below(n: u32): u32` - random u32 in 0 .. n-1 (rnd() only takes a constant, so a large random number is reduced with %)
- `math_rand(lo: i32, hi: i32): i32` - random integer in lo .. hi (both included)
- `math_chance(n: u32): u32` - 1 with the probability 1/n, otherwise 0
- `math_absf(v: f32): f32` - absolute value of a float
- `math_minf(a: f32, b: f32): f32` - the smaller of two floats
- `math_maxf(a: f32, b: f32): f32` - the larger of two floats
- `math_sqrtf(v: f32): f32` - Newton square root (0 for v <= 0)
- `math_stof(n: i32): f32` - n (|n| < 2^23) as a float, exact
- `math_itof(v: i32): f32` - any i32 as a float (above 2^23 the result is rounded like every f32)
- `math_ftoi_round(f: f32): i32` - float -> nearest integer (halves go to the even neighbour); |f| must be below 4194304
- `math_ffloor(f: f32): i32` - float -> integer, rounded down (the next smaller integer for negative numbers)
- `math_ftoi(f: f32): i32` - float -> integer, cut towards zero like a C cast

## input

*Keyboard and mouse*

Keyboard and mouse.

```js
kbd_poll();                       // once per frame, before asking anything
if (kbd_down(kb.KEY_LEFT) == 1)   // held right now
if (kbd_pressed(kb.KEY_SPACE) == 1)   // went down in this frame (edge)
c = kbd_char();                   // typed ASCII character with SHIFT / CAPS LOCK and key repeat
```

The numeric keypad types its digits and signs like the main keyboard. Keys held together with Ctrl or Alt are not characters (kbd_char() gives 0; kbd_event / kbd_down still report them, so Ctrl+S can be a hotkey, see kbd_ctrl and kbd_alt). The shortcuts of the VM itself - Ctrl+Alt+PgUp / PgDn (zoom), P (pause), R (reboot), S (frame rate) - never reach the program: while Ctrl and Alt are held together (kbd_system = 1) the keyboard looks empty, and a key that was pressed in such a chord stays hidden until it is let go.

```js
mouse_mode(0);                    // 0 = pixel coordinates, 1 = text cell coordinates
mouse_poll();                     // once per frame; then use mouse_x / mouse_y / mouse_btn
if (mouse_clicked() == 1) ...     // left button went down in this frame
```

**Constants**

- `KBD_REPEAT_DELAY = 30`
- `KBD_REPEAT_RATE = 4`
- `MOUSE_LEFT = 1` - masks for mouse_down() / mouse_pressed() / mouse_released() and the bits of mouse_btn
- `MOUSE_RIGHT = 2`
- `MOUSE_MIDDLE = 4`

**Variables** (readable, some writable)

- `kbd_keys: u16[4]` - the (up to 4) key codes held in the last poll, and in the poll before
- `kbd_shift: u32` - 1 while a SHIFT key is held, CAPS LOCK is a toggle
- `kbd_event: u32` - key code produced by the last poll: a fresh press or a typematic repeat, 0 = nothing
- `kbd_ctrl: u32` - 1 while a Ctrl / an Alt key is held (also during a chord that is hidden, so a program can tell)
- `kbd_system: u32` - 1 while Ctrl and Alt are held together: the VM's own shortcuts, the program sees no keys
- `kbd_masked: u16[4]` - keys that were pressed in a Ctrl+Alt chord and are still held: hidden until they are released

**Functions**

- `kbd_is_modifier(k: u32): u32` - reads the keyboard; call it once per frame before kbd_down() / kbd_pressed() / kbd_char() 1 for Shift, Control, Alt, Super and Menu keys
- `kbd_is_masked(k: u32): u32` - 1 when the key is one that was pressed in a Ctrl+Alt chord and is still held
- `kbd_mask(k: u32)`
- `kbd_poll()`
- `kbd_down(code: u32): u32` - 1 when the key is held in the last poll
- `kbd_was_down(code: u32): u32` - 1 when the key was held in the poll before the last one
- `kbd_pressed(code: u32): u32` - 1 only in the frame in which the key went down
- `kbd_released(code: u32): u32` - 1 only in the frame in which the key was let go
- `kbd_any(): u32` - 1 when at least one key is held
- `kbd_ascii(k: u32, shift: u32, caps: u32): u32` - physical key code -> ASCII for a US keyboard (0 = no character). Enter = 10, Backspace = 8, Tab = 9, Escape = 27, Delete = 127.
- `kbd_char(): u32` - the character typed in the last poll (fresh press or key repeat), 0 when there is none; nothing is typed while Ctrl or Alt is held
- `mouse_mode(text_cells: u32)` - 0 = coordinates in pixels, 1 = coordinates in text cells (the mode stays until it is changed)
- `mouse_poll()` - reads position and buttons; call it once per frame
- `mouse_down(mask: u32): u32` - button bit masks: MOUSE_LEFT = 1, MOUSE_RIGHT = 2, MOUSE_MIDDLE = 4
- `mouse_pressed(mask: u32): u32` - 1 when a button of the mask went down in this poll
- `mouse_released(mask: u32): u32` - 1 when a button of the mask went up in this poll
- `mouse_clicked(): u32` - left button went down in this poll
- `mouse_in(x: i32, y: i32, w: i32, h: i32): u32` - is the mouse inside the rectangle?

## console

*Scrolling console with line input*

A scrolling text console on top of the text device. The characters are also kept in a shadow buffer (10 bytes per cell, exactly the layout VTXT_CMD_FRAME wants), so scrolling is one memcpy plus one block transfer. The console works in at most 80 x 30 cells (video mode 1); on a bigger terminal it uses the top left 80 x 30 corner.

RAM: a 24 KB shadow buffer of the 80 x 30 screen - about 8 KB of the default 32 KB RAM are left for the program.

**Constants**

- `CON_MAX_COLS = 80`
- `CON_MAX_ROWS = 30`
- `CON_CELL = 10`

**Variables** (readable, some writable)

- `con_cur_x: u32` = 0xFFFFFFFF; - where the hardware cursor was put last (the host redraws the terminal on every CURSET, so it is sent only on change)

**Functions**

- `con_store(x: u32, y: u32, cp: u32, fg: u32, bg: u32)` - (internal) stores one cell in the shadow buffer
- `con_draw_all()` - (internal) sends the whole shadow buffer to the screen
- `console_cursor_sync()` - the hardware cursor follows the console cursor (nothing is sent while it stays where it is)
- `console_color(fg: u32, bg: u32)` - sets the colours of the following output (0xAABBGGRR)
- `console_clear()` - clears the console and moves the cursor to the top left corner
- `console_init()` - clears the screen, sizes the console from the text device and turns the cursor on; call it first
- `console_goto(x: u32, y: u32)` - moves the console cursor to the column x and the row y
- `console_scroll()` - scroll everything up by one line, the last line becomes empty
- `console_newline()` - moves to the start of the next line, scrolling at the bottom
- `console_putc(c: u32)` - prints one character; understands 10 (newline), 13, 9 (tab) and 8 (backspace)
- `console_print(s: u32)` - prints a zero terminated string
- `console_println(s: u32)` - prints a zero terminated string and a newline
- `console_print_uint(v: u32)` - prints an unsigned decimal number
- `console_print_int(v: i32)` - prints a signed decimal number
- `console_print_hex(v: u32)` - prints 8 hex digits
- `console_readline(buf: u32, max: u32): u32` - Reads a line typed on the keyboard with echo and backspace into buf (at most `max` characters plus the terminating zero), returns when Enter is pressed. Returns the length.
- `console_wait_key(): u32` - wait until the user presses any key (returns its code)

## gfx

*Pixel graphics*

Pixel graphics. Colours are 0xAABBGGRR. Everything that draws clips to the screen, so shapes may be partly (or completely) outside. gfx_w / gfx_h hold the size of the screen in pixels. Rectangles are sent to the video device one row at a time with a block transfer (much faster than plotting pixels). Translucent colours (alpha < 255) are blended with what is already on the screen by every function that uses block transfers: fill_rect, hline, sprites.

RAM: about 8 KB (the pixel row that gfx_fill_rect reuses).

**Constants**

- `GFX_ROW_MAX = 2048`

**Variables** (readable, some writable)

- `gfx_row: u32[GFX_ROW_MAX]` - identical pixels reused by gfx_fill_rect (valid for the first gfx_row_n pixels); because every pixel is the same, the buffer serves any rectangle of up to GFX_ROW_MAX pixels, several rows per block transfer

**Functions**

- `gfx_init()` - read the size of the screen again (after a video mode change)
- `gfx_set_mode(mode: u32)` - switch the video mode: 1 = 640x480, 2 = 1024x768, 3 = 1280x960
- `gfx_out(port: u32, value: u32)` - writes a value to a port of the video device (low level)
- `gfx_clear(color: u32)` - fills the screen with a colour; gfx_clear(COLOR_TRANSPARENT) keeps the text layer visible
- `gfx_vsync()` - waits for the next frame (the same as sys_vsync)
- `gfx_pixel(x: i32, y: i32, color: u32)` - one pixel, clipped

## gtext

*Text in the graphics mode*

Text in the pixel graphics mode. The glyphs are the 8 x 16 pixel PxPlus IBM VGA font that the VM uses for its own text mode (ASCII 32 .. 126), one bit per pixel, 16 bytes per glyph.

```js
gtext(10, 10, addr(msg), COLOR_WHITE);          // transparent background
gtext_bg(10, 30, addr(msg), COLOR_BLACK, COLOR_YELLOW);
gtext_scale = 2;                                // 2x, 3x or 4x bigger letters (1 = normal)
```

RAM: about 130 KB together with lib/gfx (the glyph caches are 64 KB and 48 KB), so a program that imports it has to declare ram(size: 262144) - the default RAM of a program is only 32 KB.

**Constants**

- `GTEXT_SLOTS = 128` - Glyph caches: building a glyph from its bits costs thousands of VM instructions (about 5 000 in the normal size, 20 000 at gtext_scale = 2), drawing a finished one is a single block transfer. Every glyph that is drawn in the normal size or twice as big on a transparent background is remembered (per character and colour, 2-way set associative), so text that is redrawn every frame is cheap after the first time - and gtext_prepare() can do the first time in advance. The caches take GTEXT_SLOTS * 512 and GTEXT_BIG_SLOTS * 2048 bytes of RAM - lower the constants for smaller programs (they must be even). Letters in other sizes (3x, 4x) and letters on a coloured background are built every time.
- `GTEXT_BIG_SLOTS = 24`

**Functions**

- `gtext_render(dst: u32, c: u32, fg: u32, bg: u32, sc: u32)` - draws the glyph c scaled sc times into the RGBA buffer at dst (8*sc x 16*sc pixels)
- `gtext_lookup(c: u32, fg: u32, sc: u32, cache: u32, kc: u32, kf: u32, slots: u32, bytes: u32): u32` - the slot of a glyph cache that holds the glyph c in the colour fg, rendered at the scale sc on a miss. cache = the pixels, kc / kf = the arrays with the characters and colours of the slots, bytes = size of a slot
- `gtext_slot(c: u32, fg: u32): u32` - index of the slot of the normal size cache
- `gtext_slot_big(c: u32, fg: u32): u32` - index of the slot of the cache of the double size
- `gtext_prepare(s: u32, fg: u32)` - Builds the glyphs of a string in the colour fg into the cache for the current gtext_scale (1 or 2) without drawing anything. Call it once at the start with the characters that will be needed, and the first redraw is as fast as every later one.
- `gtext_char(x: i32, y: i32, c: u32, fg: u32, bg: u32)` - one character with its top left corner at (x, y); bg = 0 keeps the background transparent
- `gtext_bg(x: i32, y: i32, s: u32, fg: u32, bg: u32)` - string with a background colour behind every character
- `gtext(x: i32, y: i32, s: u32, fg: u32)` - zero terminated string with a transparent background
- `gtext_width(s: u32): i32` - width of a string in pixels
- `gtext_height(): i32` - height of a line of text in pixels (16 times gtext_scale)
- `gtext_center(x: i32, w: i32, y: i32, s: u32, fg: u32)` - string centered inside the pixel columns x .. x + w - 1
- `gtext_right(x: i32, y: i32, s: u32, fg: u32)` - string with its right end at x (e.g. for numbers)
- `gtext_format(v: i32)` - formats v into gtext_num (zero terminated)
- `gtext_int(x: i32, y: i32, v: i32, fg: u32)` - signed decimal number, left aligned at x
- `gtext_int_right(x: i32, y: i32, v: i32, fg: u32)` - signed decimal number, right aligned at x

## audio

*Sound*

Sound: builds an 8 bit mono WAV in RAM (8 kHz, up to 2 seconds) and plays it through the audio device. Several tones and pauses can be chained before a single audio_play().

```js
audio_reset();
audio_tone(audio_note_freq(60), 200, AUDIO_SINE);     // middle C for 200 ms
audio_silence(50);
audio_tone(audio_note_freq(64), 200, AUDIO_SINE);
audio_play();
audio_beep(440, 100);                                 // shortcut for a single square beep
```

RAM: about 16 KB for the sound (2 seconds at 8 kHz).

**Constants**

- `AUDIO_RATE = 8000`
- `AUDIO_MAX = 16000`
- `AUDIO_SQUARE = 0`
- `AUDIO_SINE = 1`
- `AUDIO_TRIANGLE = 2`
- `AUDIO_SAW = 3`
- `AUDIO_NOISE = 4`

**Variables** (readable, some writable)

- `audio_n: u32` - samples written so far
- `audio_vol: i32` = 90; - amplitude 0 .. 127 (default 90)
- `audio_ramp: u32` = 48; - Every tone fades in and out over this many samples (8 samples = 1 ms, default 48 = 6 ms; 0 = no fading). Without it a tone ends at a random point of the wave and the jump from there to silence is heard as a click.
- `audio_sin: i16[256]` - frequencies of the 12 notes C .. B in the octave of the middle C (MIDI notes 60 .. 71) one period of the sine, -128 .. 128 (made once at the start)

**Functions**

- `audio_header()` - the constant part of the WAV header (everything except the two sizes)
- `audio_reset()` - throw away the recorded samples and start a new sound
- `audio_sample(v: i32)` - appends one sample, -128 .. 127 (0 = silence)
- `audio_note_freq(midi: u32): u32` - frequency of a MIDI note number (60 = middle C, 69 = A 440 Hz)
- `audio_tone(freq: u32, ms: u32, wave: u32)` - a tone of `ms` milliseconds; wave = AUDIO_SQUARE / SINE / TRIANGLE / SAW / NOISE. It fades in and out (audio_ramp), so its first and its last sample are silence (128) and chained tones do not click. (A tone costs about 25 VM instructions per sample, 8000 samples = one second of sound.)
- `audio_silence(ms: u32)`
- `audio_play(): u32` - sends the recorded sound to the speaker, returns 1 when the device took it
- `audio_beep(freq: u32, ms: u32)` - one square wave beep

## part

*Partition table: volumes (logical disks)*

The partition table: it divides a disk into logical disks, called volumes (the first is "volume0"). Sector 0 of the disk is reserved for a boot loader, sector 1 holds the table:

```js
byte 0 .. 7     volume 0: [i32 BeginLBA] [i32 EndLBA]   (little endian)
byte 8 .. 15    volume 1: [i32 BeginLBA] [i32 EndLBA]
...             64 volumes at most; a slot of 8 zero bytes is free
```

BeginLBA is the first sector of the volume and EndLBA the last one (included), so the volume has End - Begin + 1 sectors. Volumes lie between sector 2 and the end of the disk and do not overlap. The numbers of the volumes never change: deleting volume0 leaves volume1 where it is. The table does not say what is on a volume - a volume may hold any file system (lib/fs recognises its own by the magic number in the first sector of the volume, see part_probe_magic).

```js
part_init(std.BUS_DEV_DISK0);                  // an empty table (the old volumes are forgotten)
v = part_add_size(std.BUS_DEV_DISK0, 1000);    // volume0: 1000 sectors in the first free place
part_load(std.BUS_DEV_DISK0);
for (i of 0 .. PART_MAX) { if (part_entry(i) == 1) { ... part_begin, part_end, part_size ... } }
```

Every function that can fail returns 0 (or -1) and leaves the reason in part_error, see part_text(). RAM: about 1 KB.

- `PART_TABLE_LBA = 1`
- `PART_MAX = 64`
- `PART_FIRST_LBA = 2`
- `PART_MAGIC_MFAT = 0x5441464D` - the magic number at byte 16 of the first sector of a volume that holds lib/fs
- `PART_OK = 0`

**Variables** (readable, some writable)

**Functions**

## fs

*Fat-like file system with mount points*

A FAT style file system for the volumes of a partitioned disk (lib/part): files, directories, attributes and the date and time of the last change. Up to FS_MAX_MOUNTS volumes can be in use at the same time. Everything is written through to the disk at once, so a disk that was unmounted - or just left - is consistent.

The namespace. There is one tree for all volumes. Its root "/" is virtual: it contains nothing but the mount points, which are directories with a name of their own, and it cannot be changed. A volume appears below its mount point:

```js
part_init(std.BUS_DEV_DISK0);                  // once per disk: an empty partition table
v = part_add_size(std.BUS_DEV_DISK0, 2000);    // volume 0
fs_format(std.BUS_DEV_DISK0, v, addr(label));  // a volume needs a label of 1 .. 48 characters
fs_mount(std.BUS_DEV_DISK0, v, addr(name));    // name = "DATA": the volume is now "/DATA"
fs_mkdir(addr(path_docs));                     // "/DATA/DOCS"
h = fs_open(addr(path_file), FS_WRITE);        // "/DATA/DOCS/NOTE.TXT" is created
fs_write(h, addr(text), len);
fs_close(h);                                   // the size and the time are stored now
fs_list_begin(addr(path_docs));
while (fs_list_next() == 1) { ... fs_ent_name, fs_ent_size, fs_ent_date, fs_ent_time ... }
```

Where the mount points are kept: the table of mounted volumes lives in RAM, but the name a volume likes to be mounted under is stored in the header of the volume itself (fs_set_mountname). A disk therefore describes itself and fs_automount() puts all its volumes into the tree without any configuration file; a volume without such a name is mounted as "D0V1" (disk 0, volume 1). ".." in the root of a volume leads back to "/". Files cannot be renamed or moved from one volume to another.

Layout of a volume (like FAT16 with 512 byte clusters): reserved sectors (the boot sector of the volume: bytes 0 .. 15 stay free for a boot loader, the file system header follows at byte 16), the file allocation table (one u16 per cluster: 0 = free, 0xFFFF = last cluster of a file), then the clusters from number 2; the root directory is cluster 2 and grows like any other directory. A directory entry has the 32 bytes of FAT: an 8.3 name, attributes, created / changed / accessed times and dates in the packed FAT format (2 second resolution, years 1980 - 2107), the first cluster and the size.

Names are 8.3 (NAME.EXT), letters are made upper case, directories are separated by "/". A path without a leading slash starts in the current directory (fs_chdir); "." and ".." work. No long names, at most 65 524 clusters (32 MB) per volume, one cluster = one sector. Directories cannot be moved into themselves; open files cannot be removed or renamed. Every function that can fail returns 0 (or -1) and leaves a reason in fs_error, see fs_error_text(); lib/fsck checks a volume for consistency.

RAM: about 5 KB. The functions use shared buffers, so the library is not for concurrent use.

## fsck

*Consistency check of a volume*

Consistency check of a volume of lib/fs (like fsck / chkdsk): it walks the whole directory tree and compares it with the allocation table.

```js
n = fsck_run(std.BUS_DEV_DISK0, 1, 0);      // volume 1; 0 = only look, 1 = also free lost clusters
if (n == 0) { ... fsck_files, fsck_dirs, fsck_used, fsck_free ... }
else if (n > 0) { ... fsck_log holds the first problems, one per line ... }
else { ... fs_error ... }                   // the volume could not be checked
```

What is checked: the table entries 0 and 1, the volume label, every directory chain and every file chain (clusters that leave the volume, free clusters inside a chain, loops), that no cluster belongs to two files or directories (cross links), that the size of a file fits the length of its chain, that "." and ".." of every directory point to the right places, directories with a size, invalid and duplicate names (the first 64 entries of every directory), impossible dates and times, and clusters that are marked as used but belong to nobody (lost clusters). With fix = 1 the lost clusters are given back; the other problems are only reported - they need a human decision. A volume that is mounted must have no open files; a volume that is not mounted is mounted for the time of the check.

fsck_dirs counts the directories below the root. RAM: about 11 KB (a bit for every cluster, the list of problems), so a program that uses it needs ram(size: 65536) or more.

**Constants**

- `FSCK_STACK = 256`
- `FSCK_LOG_SIZE = 1536`
- `FSCK_NAMES = 64`
- `FSCK_NO_LABEL = 0` - kinds of problems
- `FSCK_BAD_TABLE = 1`
- `FSCK_DIR_CHAIN = 2`
- `FSCK_FILE_CHAIN = 3`
- `FSCK_SIZE = 4`
- `FSCK_CROSS = 5`
- `FSCK_NAME = 6`
- `FSCK_DUPLICATE = 7`
- `FSCK_DIR_SIZE = 8`
- `FSCK_DOT = 9`
- `FSCK_DOTDOT = 10`
- `FSCK_DATE = 11`
- `FSCK_LOST = 12`
- `FSCK_TOO_DEEP = 13`

**Variables** (readable, some writable)

- `fsck_files: u32` - what the last fsck_run found
- `fsck_used: u32` - clusters that belong to files and directories
- `fsck_free: u32` - free clusters
- `fsck_fixed: u32` - the lost clusters that were given back
- `fsck_errors: u32` - the number of problems, and the first of them as text: one line each ("message (number)")

**Functions**

- `fsck_problem(kind: u32, n: u32)` - adds a problem: its kind (FSCK_*) and a number that says where
- `fsck_claim(c: u32): u32` - marks a cluster as used by the tree; 0 (and a problem) when something else owns it already
- `fsck_is_owned(c: u32): u32`
- `fsck_chain(first: u32): u32` - Follows the chain of a file from its first cluster and claims every cluster: the number of clusters, or FS_NONE when the chain is damaged.
- `fsck_name_ok(e: u32): u32` - is the 8.3 name at e a possible name? (letters, digits and the allowed signs, blanks only at the end)
- `fsck_one_date(d: u32): u32` - a packed date: 0 (= not set) or a month 1 .. 12 and a day 1 .. 31
- `fsck_date_ok(e: u32): u32` - the dates and the time of the change of an entry at e are possible values
- `fsck_scan_dir(dir: u32, parent: u32)` - checks one directory: the entries, and the chains of its files; subdirectories go to the stack
- `fsck_run(dev: u32, vol: u32, fix: u32): i32` - Checks the volume `vol` of the disk `dev`. Returns the number of problems (0 = the volume is consistent) or -1 when it could not be checked (fs_error tells why). With fix = 1 lost clusters are freed.

## arr
